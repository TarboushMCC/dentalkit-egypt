\section{Project Overview}
% ══════════════════════════════════════════════════════════════════════════════

\textbf{DentalKit Egypt} is Egypt's first specialized e-commerce marketplace built exclusively for dental university students. The platform solves a recurring problem that dental students face every academic year: sourcing the exact equipment, instruments, and consumables required by their specific university for each academic year, bundled at the best price, from a single trusted source.

\begin{infobox}{Platform at a Glance}
\begin{tabular}{@{}ll@{}}
\textbf{Platform Type}    & Full-stack marketplace (B2C, student-focused) \\
\textbf{Market}           & Egyptian dental universities \\
\textbf{Primary Currency} & Egyptian Pound (EGP) \\
\textbf{Payment Methods}  & InstaPay, Cash on Delivery \\
\textbf{Languages}        & Arabic + English (bilingual product catalogue) \\
\end{tabular}
\end{infobox}

\subsection{Problem Statement}

Each dental faculty in Egypt assigns a mandatory equipment list to students at the start of every academic year. Currently, students must:

\begin{enumerate}[leftmargin=*]
  \item Collect a handwritten or PDF list from the faculty office.
  \item Shop individually from multiple specialized medical-supply vendors across Cairo and other governorates.
  \item Compare prices, verify item quality, and handle logistics themselves.
  \item Risk buying wrong items or missing a required instrument.
\end{enumerate}

This process wastes weeks of student time, is susceptible to price gouging, and offers no quality guarantee. DentalKit Egypt consolidates the entire process into a single online order.

\subsection{Solution}

DentalKit Egypt provides:

\begin{itemize}[leftmargin=*]
  \item \textbf{University-matched packages}: Pre-curated kits built against each university's official requirement list, per academic year.
  \item \textbf{Individual product shop}: Students can also purchase standalone instruments or consumables.
  \item \textbf{Transparent pricing}: Public compare prices and coupon discounts.
  \item \textbf{Order tracking}: Real-time order status from confirmation to delivery.
  \item \textbf{Wishlist}: Save items across sessions.
  \item \textbf{Admin dashboard}: Full operations panel for managing inventory, orders, and universities.
\end{itemize}

\subsection{Directory Structure}

The project follows Next.js App Router conventions with route groups for logical separation:

\begin{lstlisting}[language=bash, caption={High-level directory tree}]

    (shop)/             # Public storefront (no auth required)
      page.tsx          # Homepage
      packages/         # Package listing + detail pages
      products/         # Individual product shop
      universities/     # University browser + year pages
      cart/             # Shopping cart
      find-kit/         # Kit finder wizard
    (auth)/             # Authentication pages (no navbar/footer)
      login/
      register/
    checkout/           # Protected: requires login
    dashboard/          # Protected: student area
      orders/
      wishlist/
      profile/
    admin/              # Protected: ADMIN or SUPER_ADMIN only
      orders/
      packages/
      universities/
    api/                # REST API routes
      auth/
      cart/
      coupons/
      orders/
      packages/
      payments/
      products/
      universities/
      wishlist/
      admin/
  components/
    home/               # Homepage sections (Hero, HowItWorks, etc.)
    layout/             # Navbar, Footer
    ui/                 # shadcn/ui primitives
    providers/          # SessionProvider wrapper
    SEO/                # StructuredData JSON-LD
  lib/
    db.ts               # Prisma client singleton
    utils.ts            # cn() and shared helpers
  auth.ts               # Full NextAuth config (server-side)
  auth.config.ts        # Edge-safe NextAuth config (used in proxy)
  proxy.ts              # Next.js 16 middleware (replaces middleware.ts)
prisma/
  schema.prisma         # Full data model
\end{lstlisting}

\subsection{Route Architecture}

\begin{infobox}{Route Groups}
Next.js route groups (\texttt{(shop)}, \texttt{(auth)}) share layouts without affecting URLs. The storefront layout wraps pages with a full Navbar and Footer; the auth group uses a minimal centered layout; the checkout and dashboard routes are fully protected by \texttt{src/proxy.ts}.
\end{infobox}

\subsection{Authentication Architecture}

DentalKit Egypt uses \textbf{NextAuth v5} with a split-config pattern required by Next.js 16:

\begin{itemize}[leftmargin=*]
  \item \textbf{\texttt{auth.config.ts}} — Edge-safe config: no Prisma imports. Contains the \texttt{authorized} callback that drives route protection in the proxy, and the \texttt{session} callback that maps \texttt{token.role} onto \texttt{session.user.role}.
  \item \textbf{\texttt{auth.ts}} — Full server config: imports Prisma adapter, defines the credentials provider, and the JWT session callbacks.
  \item \textbf{\texttt{src/proxy.ts}} — Next.js 16's replacement for \texttt{middleware.ts}. Runs \texttt{NextAuth(authConfig)} and exports the matcher config.
\end{itemize}

Three role levels exist:

\begin{center}
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{Role}         & \textbf{Access}              & \textbf{Redirect on login} \\
\midrule
\texttt{STUDENT}      & Shop + Dashboard             & \texttt{/dashboard} \\
\texttt{ADMIN}        & Shop + Dashboard + Admin     & \texttt{/admin} \\
\texttt{SUPER\_ADMIN} & Full platform access         & \texttt{/admin} \\
\bottomrule
\end{tabular}
\end{center}

\section{Database Schema}
% ══════════════════════════════════════════════════════════════════════════════

The PostgreSQL schema is managed by Prisma and contains 17 models organized into five logical groups:

\subsection{Entity Groups}

\subsubsection{Authentication (NextAuth)}
\texttt{User}, \texttt{Account}, \texttt{Session}, \texttt{VerificationToken} — standard NextAuth tables. The \texttt{User} model is extended with a \texttt{role} enum (\texttt{STUDENT / ADMIN / SUPER\_ADMIN}), a \texttt{password} field for credentials auth, and a \texttt{studentProfile} relation.

\subsubsection{Academic Structure}
\begin{itemize}[leftmargin=*]
  \item \textbf{University} — Egyptian dental faculties with bilingual names (\texttt{name}/\texttt{nameAr}), slugs, logo URLs, and sort order. Linked to \texttt{AcademicYear} and \texttt{Package}.
  \item \textbf{AcademicYear} — Year levels (First Year through Fifth Year) per university, each with a slug used in the URL (\texttt{/universities/cairo-uni/first-year}).
  \item \textbf{StudentProfile} — Optional profile record linking a student to their university and year, plus phone, address, and governorate for shipping pre-fill.
\end{itemize}

\subsubsection{Product Catalogue}
\begin{itemize}[leftmargin=*]
  \item \textbf{Category} — Hierarchical product grouping (instruments, consumables, lab equipment, etc.).
  \item \textbf{Product} — Individual items with SKU, bilingual name/description, price, compare price, stock level with low-stock alert, image array, and tags.
  \item \textbf{Package} — A curated bundle tied to a specific \texttt{University} + \texttt{AcademicYear}. Contains \texttt{isRequired} flag. Items are defined via \texttt{PackageItem} (join table with quantity).
\end{itemize}

\subsubsection{Commerce}
\begin{itemize}[leftmargin=*]
  \item \textbf{CartItem} — Polymorphic: can hold either a \texttt{productId} or a \texttt{packageId}.
  \item \textbf{Order} / \textbf{OrderItem} / \textbf{OrderStatusLog} — Full order lifecycle with shipping address fields, coupon code, discount, shipping cost, and a status log for audit trail.
  \item \textbf{Payment} — Linked 1:1 to an order. Stores provider (\texttt{instapay}), reference number, raw webhook JSON, and refund fields.
  \item \textbf{WishlistItem} — Polymorphic like CartItem.
  \item \textbf{Review} — Moderated rating + text review, attachable to product or package.
\end{itemize}

\subsubsection{Marketing}
\begin{itemize}[leftmargin=*]
  \item \textbf{Coupon} — Percentage or fixed-amount codes with usage limits, minimum order threshold, maximum discount cap, and validity window.
  \item \textbf{Banner} — Homepage promotional banners.
  \item \textbf{SiteSettings} — Key-value store for runtime configuration.
\end{itemize}

\subsection{Order Lifecycle Enums}

\begin{multicols}{2}
\textbf{OrderStatus}
\begin{itemize}[noitemsep]
  \item \texttt{PENDING}
  \item \texttt{CONFIRMED}
  \item \texttt{PROCESSING}
  \item \texttt{SHIPPED}
  \item \texttt{DELIVERED}
  \item \texttt{CANCELLED}
  \item \texttt{REFUNDED}
\end{itemize}

\textbf{PaymentStatus}
\begin{itemize}[noitemsep]

  \item \texttt{FAILED}
  \item \texttt{REFUNDED}
  \item \texttt{PARTIALLY\_REFUNDED}
\end{itemize}
\end{multicols}

\section{Payment Integration}
% ══════════════════════════════════════════════════════════════════════════════

\subsection{InstaPay}

InstaPay is Egypt's national instant payment network operated through local banks. DentalKit Egypt integrates it as the primary digital payment method:

\begin{enumerate}[leftmargin=*]
  \item Student selects "InstaPay" on the checkout page.
  \item The checkout page calls \texttt{POST /api/payments/instapay} to create a payment record with status \texttt{PENDING}.
  \item A QR code / InstaPay phone number is displayed.
  \item Student completes the transfer from their banking app.
  \item InstaPay sends a webhook to \texttt{/api/payments/instapay/webhook}.
  \item The webhook handler verifies the payload, marks the \texttt{Payment} as \texttt{PAID}, and updates the \texttt{Order.paymentStatus} to \texttt{PAID}.
\end{enumerate}

\subsection{Cash on Delivery}

For students outside digital payment coverage, Cash on Delivery (COD) is available. Orders placed with COD are created with \texttt{paymentStatus = UNPAID} and \texttt{paymentMethod = "cod"}. The admin manually marks payment received upon delivery.

\section{SEO \& AI Discoverability}
% ══════════════════════════════════════════════════════════════════════════════

The platform is built with strong SEO and AI-crawler discoverability from the ground up:

\begin{itemize}[leftmargin=*]
  \item \textbf{\texttt{src/app/sitemap.ts}} — Dynamically generates XML sitemap including all university, year, and package URLs.
  \item \textbf{\texttt{src/app/robots.ts}} — Crawler permission rules.
  \item \textbf{\texttt{public/llms.txt}} — Summary file for AI language model indexers (per the \texttt{llms.txt} standard).
  \item \textbf{\texttt{public/llms-full.txt}} — Full detailed content for AI crawlers.
  \item \textbf{\texttt{src/components/SEO/StructuredData.tsx}} — Injects JSON-LD schemas: \texttt{Product}, \texttt{BreadcrumbList}, \texttt{Organization}, enabling rich snippets in Google Search.
  \item All product and package pages include \texttt{generateMetadata()} for per-page Open Graph tags, meta descriptions, and canonical URLs.
\end{itemize}

\section{Animations \& UX}
% ══════════════════════════════════════════════════════════════════════════════

Framer Motion v12 is used throughout the storefront for a polished, clinical feel:

\begin{itemize}[leftmargin=*]
  \item \textbf{Page transitions} — Fade + slight Y-slide on route change via a shared layout wrapper.
  \item \textbf{Stagger children} — University cards and package cards stagger-animate into view using \texttt{staggerChildren: 0.06}.
  \item \textbf{Scroll-triggered} — Sections on the homepage animate in as the user scrolls using \texttt{whileInView}.
  \item \textbf{Button feedback} — \texttt{whileTap: \{ scale: 0.96 \}} on primary CTAs.
  \item \textbf{Cart badge} — Numeric badge on the Navbar cart icon animates with \texttt{AnimatePresence} when count changes.
  \item All animation variants are defined in \texttt{src/lib/motion.ts} for consistent reuse.
\end{itemize}
